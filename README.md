## 维护状态说明

### 为什么停止维护

这个项目最初是为了模拟 LED 点阵屏的显示效果而写的，功能上还算完整，但在两年的时间里经历了大量迭代和临时补丁，代码结构逐渐变得难以维护：

- 核心类膨胀，职责高度耦合
- 动画逻辑以长 if-elif 链堆叠，难以扩展和测试
- 历史上为了兼容旧节目单文件，积累了不少"补丁式"逻辑

继续在原结构上修改的成本，已经超过了重新设计的成本。与其让它在一个不可持续的结构上继续腐坏，不如让它停在一个**可用的最终状态**，把精力留给其他更重要的事情。

### 这对你意味着什么

### 如果你还在使用它

## 关于这个项目的一点坦诚

这个项目是我**学完 Python 之后手搓的第一个完整项目**。

那时候的情况大致是这样的：

- **有想法**：我很想把 LED 点阵屏的显示效果搬到 PC 上模拟出来，  让它能跑动画、能排节目、能录 GIF。这个想法从头到尾都很明确。
- **还没有 AI 编程工具**：当时没有什么"让 AI 帮我写代码"的选项，  从第一行到最后一行，都是自己查文档、试错、调试出来的。
- **软件工程方面还很稚嫩**：我知道怎么让代码"跑起来"，  但对分层、解耦、可测试性、依赖注入这些概念，基本没有实践过。

所以你现在看到的这份代码，是一个 **"能跑"优先于"能维护"** 的产物，但它不是一个按工程规范设计的项目。后来我慢慢意识到：**"力大砖飞"能飞，但飞完要修跑道。** 这个项目的问题不是它不努力，而是它是在一个还没学会修跑道的阶段被造出来的。

我选择把它停在这里，而不是硬撑着继续修补，原因很简单：
以我现在的判断，**在一副已经拧巴的骨架上继续加零件，比重新设计一次更昂贵**。而我也不想用"为了不辜负用户"当理由，把一个自己都不愿意再读的代码库长期挂在"维护中"的状态里。

这个项目对我来说是一段真实的学习痕迹：**一个还没有工程能力的阶段，认真做出的一个想解决问题的东西。**

如果你 fork 它、修它、或者受它启发做出新东西，我很高兴。
如果它只是安静地躺在这里，被人偶尔翻出来看看，
那也是它应得的归宿。

**它已经完成了它的使命。**

## 项目简介

LED 屏幕模拟器，用于在 PC 上模拟 LED 点阵屏的显示效果，
支持文字滚动、闪烁、扇形展开、百叶窗、窗户开合、跳跃、翻屏等多种动画特效，
并支持节目单调度、多屏联动、背景遮罩和 GIF 录制。

### 主要特性

- **多种显示特效**：静止、闪烁、各方向滚动、移到中间、跳跃移动、
  扇形圆形、百叶窗、窗户开合、翻屏、上下反复跳跃等
- **节目单系统**：按时间或触发器切换节目，支持跨屏联动
- **背景支持**：纯色、图片（平铺 / 居中 / 填充 / 拉伸 / 适应）
- **GIF 录制**：把运行效果录成 GIF，支持从节目开头录制
- **单色 / RGB 双模式**：支持 1-bit 单色屏和 RGB 彩色屏
- **自定义字体**：支持中英文字体、字号、加粗、缩放、多行排版

### 运行环境

- Python 3.8+
- PyQt5
- Pillow
- imageio
- numpy

详见requirements.txt

> 依赖版本未锁定，未来版本变化可能导致无法运行。
> 如需长期使用，建议 fork 后自行锁定依赖版本。
